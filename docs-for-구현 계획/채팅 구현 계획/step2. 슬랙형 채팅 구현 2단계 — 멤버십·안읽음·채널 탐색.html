step2 — 슬랙형 채팅 구현 2단계 (멤버십·안읽음·채널 탐색)

1단계의 "모두가 모든 채널을 본다"를 넘어, 채널 가입/탈퇴·공개/비공개·안읽음 카운트·채널 탐색을 붙여 실제로 쓸 만한 사내 채팅으로 만든다.

전제

step1 완료 = 채널 생성·진입·메시지 송수신·실시간 수신이 동작하는 상태. 2단계는 여기에 "누가 어떤 채널에 속하는가 + 안 읽은 게 몇 개인가"를 추가한다.

결론 — 이번 단계의 핵심은 새 테이블 2개

핵심 판단
현재 멤버십은 워크스페이스 단위(meeting_workspace_members)뿐이라, 채널 단위 가입과 비공개 채널을 표현할 수 없다.
→ 채널 멤버십과 읽음 상태 테이블을 새로 만든다. 안읽음은 "마지막 읽은 메시지 이후 개수"로 계산.

2단계 범위 (Scope)

  • 채널 가입 / 나가기 (공개 채널은 누구나 가입, 비공개는 초대 필요)
  • 채널 공개(public) / 비공개(private) 구분
  • 안읽음 카운트: 채널별 미읽음 배지 + 레일 채팅 아이콘 합계 배지
  • 채널 탐색: 가입 안 한 공개 채널 목록 + 검색해서 가입
  • 사이드바: 내 채널(가입한 것)만 기본 표시, 안읽음 우선 정렬
  • 멤버 초대 (비공개 채널에 조직 구성원 추가)
비범위: @멘션·검색·스레드·반응·파일 (3단계 이후).

백엔드 작업

DB — 신규 테이블 server src/database/schema.ts

// 채널(룸) 단위 멤버십
meeting_room_members
  id            text  pk
  room_id       text  fk → meeting_rooms.id (cascade)
  user_id       text  fk → users.id (cascade)
  role          text  'owner' | 'member'         // 채널 관리 권한
  created_at    text
  (unique: room_id + user_id)

// 채널별 읽음 상태 (안읽음 계산용)
meeting_room_reads
  id                  text  pk
  room_id             text  fk → meeting_rooms.id (cascade)
  user_id             text  fk → users.id (cascade)
  last_read_at        text                         // 마지막으로 읽은 시각
  last_read_message_id text nullable
  updated_at          text
  (unique: room_id + user_id)
채널 공개/비공개: meeting_rooms에 visibility('public' | 'private') 컬럼 추가. 기존 채널은 public 기본값으로 마이그레이션.

안읽음 계산 규칙 (정확성 포인트)

  • 본인이 보낸 메시지는 안읽음에 포함하지 않는다.
  • 채널을 열고 있는 동안 도착한 메시지는 즉시 읽음 처리(배지 안 올림).
  • last_read_at은 "스크롤이 맨 아래일 때"만 최신으로 갱신 — 위로 올려 과거 읽는 중엔 유지.

완료 기준 (Definition of Done)

  • 공개 채널을 탐색→가입할 수 있고, 가입한 채널만 내 사이드바에 뜬다.
  • 비공개 채널은 초대받은 사람만 보이고 들어갈 수 있다.
  • 다른 사람이 메시지를 보내면 해당 채널에 안읽음 배지가 뜨고, 레일 아이콘에 합계가 뜬다.
  • 채널을 열면 배지가 사라진다(읽음 처리).
  • 채널 나가기 시 내 사이드바에서 사라지고, DM 나가기 동작과 충돌하지 않는다.
