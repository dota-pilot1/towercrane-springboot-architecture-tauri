step3 — 슬랙형 채팅 구현 3단계 (멘션·알림·검색)

대화량이 늘면 "나를 부른 메시지"와 "예전에 본 그 메시지"를 빠르게 찾는 게 핵심이 된다. @멘션 · 멘션 알림 · 메시지 검색을 붙인다.

전제

step2 완료 = 채널 멤버십·안읽음·탐색이 동작. 3단계는 메시지 본문을 "구조적으로" 다루기 시작한다(멘션 파싱·인덱싱).

결론 — 멘션은 별도 테이블, 검색은 단계적

핵심 판단
멘션은 메시지에서 @사용자를 파싱해 별도 테이블로 적재 → "내 멘션함"과 알림 배지를 빠르게 조회.
검색은 먼저 SQLite LIKE 기반 단순 검색으로 출시하고, 데이터가 커지면 FTS5 전문검색으로 승격(2-pass).

3단계 범위 (Scope)

  • 메시지 입력 중 @ 타이핑 → 멤버 자동완성, 멘션 토큰 저장
  • 멘션 받은 사람: 안읽음과 별개로 멘션 배지(빨강) + "내 멘션" 모아보기
  • @everyone(채널 전체) / @here(접속 중) 특수 멘션
  • 메시지 검색: 채널 내 검색 + 전체 검색, 결과 클릭 시 해당 메시지로 점프
  • (선택) OS 데스크톱 알림 — Tauri notification 플러그인
비범위: 스레드·반응(4단계), 파일 첨부(5단계).

// 멘션 적재 (메시지 저장 시 파싱해서 함께 insert)
meeting_mentions
  id          text  pk
  message_id  text  fk → meeting_messages.id (cascade)
  room_id     text  fk → meeting_rooms.id (cascade)
  mentioned_user_id text fk → users.id (cascade)   // @everyone/@here는 별도 처리
  mention_type text  'user' | 'everyone' | 'here'
  is_read     integer(bool) default false
  created_at  text
  (index: mentioned_user_id + is_read)

정확성 포인트

  • 멘션 파싱은 서버에서 최종 확정(클라 파싱만 믿지 않음) — 위조·없는 사용자 방지.
  • @everyone은 권한 가드(아무나 전체 알림 못 쏘게 owner/관리자 제한 고려).
  • 검색은 내가 접근 권한 있는 채널로만 한정(비공개 채널 누수 금지).
  • 메시지 점프: 검색/멘션에서 이동 시 해당 메시지가 로드 안 됐으면 "그 시점 페이지"부터 로드.

완료 기준 (Definition of Done)

  • 입력창에서 @ 치면 멤버 자동완성이 뜨고, 보낸 메시지에 멘션 칩이 보인다.
  • 멘션 받으면 멘션 배지가 뜨고, "내 멘션"에서 모아 볼 수 있다.
  • 키워드 검색으로 과거 메시지를 찾고, 클릭하면 그 메시지로 점프한다.
  • 비공개 채널 메시지가 권한 없는 사람 검색결과에 절대 안 나온다.
