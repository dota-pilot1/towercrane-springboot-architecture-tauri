step1 — 슬랙형 채팅 구현 1단계 (기본)

레일의 채팅 모듈을 켜고, 이미 있는 백엔드(워크스페이스·채널·메시지·WebSocket)를 프론트에 노출해 "단체방에서 대화"가 되게 만드는 단계.

전체 로드맵 (총 5단계, 1~3이 실사용 핵심)

단계주제성격
1 (이 문서)채팅 모듈 활성화 + 워크스페이스/채널 사이드바 + 채널 메시징기존 백엔드 노출 → MVP
2채널 멤버십·안읽음 카운트·채널 탐색·공개/비공개실제로 쓸 만한 사내 채팅
3@멘션·멘션 알림·메시지 검색협업 필수
4스레드 답글·이모지 반응고도화
5파일/이미지 첨부·핀·채널 아카이브(운영)마무리

결론 — 1단계는 "신규 구축"이 아니라 "노출"이다

핵심 판단
백엔드에는 이미 슬랙형 데이터 모델과 API가 깔려 있다. 1단계에서 새 테이블·새 인프라를 만들 필요가 거의 없다.
해야 할 일의 90%는 Tauri 프론트가 기존 워크스페이스/채널 API를 화면에 연결하는 것.

빠진 것 (이번 단계 범위 밖 — 2~3단계로)

채널 단위 읽음/안읽음 상태 테이블, 멘션·스레드·반응·파일 테이블은 아직 없음. 1단계에서는 손대지 않는다.

1단계 범위 (Scope)

  • 레일 채팅 모듈을 ready: true로 전환하고 전용 화면 연결
  • 좌측: 워크스페이스 → 채널 목록 사이드바 (DM 제외, 그룹 채널만)
  • 중앙: 채널 선택 시 메시지 목록 + 입력창 (기존 ChatView 흐름 재사용)
  • ＋ 채널 만들기 (이름·설명·roomType 선택 → POST /meeting/workspaces/:id/rooms)
  • 실시간 수신: 기존 WebSocket 구독으로 새 메시지 즉시 반영
비범위: 채널 가입/초대 UI, 안읽음 배지, 비공개 채널, 멘션, 검색, 스레드, 파일. (모두 2단계 이후) 1단계는 "워크스페이스 멤버는 그 워크스페이스의 채널을 모두 본다"는 단순 모델로 시작.

UI 규칙

메신저와 시각적으로 구분: 채널은 아바타 대신 # 프리픽스, 헤더에 채널 설명 노출. 색·토큰은 기존 규칙 준수(raw 팔레트 금지, semantic 토큰/ui-* 유틸 사용).

완료 기준 (Definition of Done)

  • 레일에서 채팅 클릭 → 워크스페이스/채널 사이드바가 뜬다.
  • ＋채널 만들기로 새 채널 생성 → 목록에 즉시 나타난다.
  • 채널 선택 → 과거 메시지 로드 + 입력·전송 동작.
  • 두 계정으로 같은 채널 접속 시, 한쪽 메시지가 다른 쪽에 실시간으로 보인다.
  • 메신저(1:1)와 채팅(그룹)이 레일에서 완전히 분리되어 서로 간섭 없음.
